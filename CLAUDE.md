# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The [Zyllo Tech](https://zyllotech.com) company website — a Vite + React 18 SPA using React Router, shadcn/ui (Radix + Tailwind), and Supabase (auth, Postgres, storage, edge functions). Developed and published through **Lovable**: pushes to the GitHub `main` branch sync into Lovable and vice versa, and production deploys happen via Lovable Publish, not from this machine. Always pull before working — a stale local checkout pushed to `main` will overwrite Lovable-side edits.

**This is NOT a Next.js project.** It was migrated from Next.js to Vite. Ignore `AGENTS.md` (stale Next.js agent rules) and Next.js entries in `.gitignore` — they are leftovers. `src/components/NextCompat.tsx` exists to wrap react-router with Next-style `Link`/hooks APIs for components written during the Next.js era.

## Commands

```bash
npm run dev          # dev server on http://localhost:8080 (not 5173 — see vite.config.ts)
npm run build        # prebuild: sitemap gen → vite build → postbuild: prerender
npm run lint         # eslint .
```

## Architecture

- `src/App.tsx` — the routing table. Every page is lazy-loaded. It also holds **legacy-slug redirects** (old service URLs, `/privacy` → `/privacy-policy`, etc.) that still receive indexed traffic; don't remove them, and add a redirect here when renaming a public URL.
- `src/pages/` — one component per route. `src/sections/` — large page-composition blocks (hero, testimonials, etc.) used by pages. `src/components/` — shared components; `src/components/ui/` is shadcn. The codebase is a `.jsx`/`.tsx` mix; match whichever the file you're touching uses.
- `src/data/` — static content is code, not a CMS: `services.js` + `service-details.js` (service catalog), `articles.ts` (blog posts), `page-faqs.js` (single source for the commercial pages' visible FAQ sections AND their FAQPage JSON-LD, both runtime and prerender), `fallback-content.js` (derives `fallbackPosts` from `articles.ts` — blog content flows articles.ts → fallback-content.js → BlogPostPage + prerender), `legal-content.js`. Editing site copy usually means editing these files.
- `src/integrations/supabase/client.ts` — the single Supabase client. It has a **deliberate hard-coded fallback** to the public anon key/URL because Lovable's custom-domain publish pipeline has been observed to skip Connector env injection (`VITE_SUPABASE_URL`/`VITE_SUPABASE_PUBLISHABLE_KEY`). Do not remove the fallback; it is the public RLS-scoped anon key, safe in the browser. `previewAuthStorage.ts` next to it is auto-generated by Lovable — do not hand-edit.
- Auth: `src/contexts/AuthContext.tsx` + `src/lib/auth.ts`; `/admin` is gated by `ProtectedRoute requireAdmin`.
- Supabase backend: migrations in `supabase/migrations/`, edge function `supabase/functions/notify-admin`. Job postings, contact/application submissions, and the application pipeline live in Postgres and are managed via the admin dashboard.
- Path alias: `@/` → `src/`.

## Tests are consistency guards, not unit tests

`src/test/` mostly cross-checks files that must agree with each other — a failure usually means two files drifted apart, not that a component broke:

- `redirects.test.ts` — every legacy path in `prerender.mjs`'s `REDIRECTS` map has a matching `<Navigate>` in `App.tsx` with the same target.
- `sitemap.test.ts` — `public/sitemap.xml` agrees with the routes derived from `services.js`/`articles.ts` and never lists a redirect source.
- `site-search-index.test.ts` — the search index only emits real routes.
- `article-links.test.ts` — inline `[text](/path)` links parse identically in `BlogPostPage.jsx`, `prerender.mjs`, and `fallback-content.js`.
- `seo-schemas.test.ts` / `jsonld-escape.test.ts` / `jobposting-jsonld.test.tsx` — JSON-LD builders keep required fields and escape safely.

Run `npm test` after touching routes, `public/sitemap.xml`, anything in `src/data/`, or `scripts/prerender.mjs`. Note eslint only covers `.ts`/`.tsx` — `.jsx` files are outside its scope.

## Bundle-weight rule

`src/lib/site-search-index.js` statically imports `articles.ts` (~138KB chunk), so it must only ever be loaded via dynamic `import()` from the search UIs. A static import from anything mounted in the `Header` drags the whole blog archive into the main bundle. The same logic applies to the Supabase client on content pages — `BlogPostPage` loads it via `await import(...)` inside an effect so it never gates first paint.

## Build-time SEO pipeline (load-bearing)

SEO is a standing priority for this site; the build has two custom steps in `scripts/`:

- `generate-sitemap.mjs` (prebuild) — fetches live open job postings from Supabase and injects `/careers/:id` URLs into `public/sitemap.xml`.
- `prerender.mjs` (postbuild) — writes `dist/<route>/index.html` for every public route with that route's real title, meta description, canonical, OG tags, JSON-LD, and a semantic HTML body. This is what non-rendering crawlers (Googlebot pre-render, GPTBot, ClaudeBot, etc.) see; the browser SPA replaces `#root` wholesale on top of it, so no hydration concerns.

Both scripts are **deliberately fail-soft** (log and exit 0 on any error) — a missing sitemap entry or prerender is smaller than a broken deploy. Keep that property.

Consequences:
- **Adding a public page** requires five touches: route in `App.tsx`, entry in the `CORE` list (or data-driven section) of `scripts/prerender.mjs`, URL in `public/sitemap.xml`, an `SEOHead` usage in the page, and an entry in the `CORE_PAGES` list of `src/lib/site-search-index.js` (enforced by `site-search-index.test.ts`).
- `src/components/SEOHead.tsx` exports the site constants and JSON-LD schema builders used both at runtime (react-helmet-async) and by `prerender.mjs` at build time — changes there affect both.
- Service and blog prerenders derive from the `src/data/` files, so content edits there flow into prerendered HTML automatically on the next build.


Static hosting files in `public/` (`_redirects`, `robots.txt`, `llms.txt`, `sitemap.xml`, `manifest.json`) ship as-is next to the prerendered `dist/` output. The host ignores `_redirects` — real redirects for crawlers are the prerendered stub pages plus the `App.tsx` `<Navigate>` routes.
